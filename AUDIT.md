# Grammar and Zed extension audit

Snapshot: 2026-11-05. This is a targeted audit, not a complete language conformance review.
The five grammars and `undivisible/zed-extensions` had no open pull requests at the time of inspection.

## Findings

- **V — regeneration is blocked.** `grammar.js` declares ten external tokens, but `src/parser.c` has zero external tokens and the repository contains no scanner source. Generating with Tree-sitter 0.25.10 produces references to missing `tree_sitter_v_external_scanner_*` symbols. Recover the matching scanner and grammar, or deliberately migrate both together; do not overwrite the working parser with that generated output.
- **V — corpus and parser disagree.** In a temporary Tree-sitter project using the checked-in parser and `corpus/` as `test/corpus/`, Tree-sitter 0.25.10 reported 39 passing and 96 failing cases. For example, the array initializer expectations disagree on `identifier_list` versus `expression_list` and `builtin_type` versus `type_identifier`. Review expected trees against the intended grammar before updating them; failures are not necessarily syntax errors.
- **V — highlight query.** The query used a nonexistent `builtin_type` node and failed to compile. This audit removes that pattern and adds a query-compilation test. The remaining `type_identifier` pattern still captures named types.
- **HolyC — limited but exercised.** All 10 existing corpus cases passed and `queries/highlights.scm` compiled against the parser. The README already identifies missing classes, `extern`, preprocessor, and full declarators. The package metadata disagree about version and license; verify provenance before changing license declarations.
- **Crystal — class methods and coverage.** Valid `def self.hello` class methods failed because the grammar placed the receiver before `def`; a separate fix moves it after `def` and adds corpus coverage. The grammar lacks many constructs including Crystal's `if` expressions and modules. The repository previously had no Tree-sitter corpus cases; parsing the sample without errors does not establish semantic correctness. See the [Crystal class method reference](https://crystal-lang.org/reference/1.19/syntax_and_semantics/class_methods.html) and [control flow tutorial](https://crystal-lang.org/reference/1.5/tutorials/basics/50_control_flow.html).
- **Nim — indentation is not modeled.** `grammar.js` treats all whitespace as extras. A dedented `echo` after a procedure is incorrectly parsed inside its body, and the checked-in `sample.nim` produces an error at the object field. Nim is indentation-sensitive; see the [Nim manual](https://nim-lang.org/docs/manual.html). It has no Tree-sitter corpus cases. Fixing this requires an indentation-aware design, not just adding productions.
- **LOLCODE — multiline comments fail.** The grammar limits the content of `OBTW … TLDR` to a single line; a two-line comment yields an `ERROR`, contrary to the [LOLCODE 1.2 specification](https://raw.githubusercontent.com/justinmeza/lolcode-spec/master/v1.2/lolcode-spec-v1.2.md). There are no Tree-sitter corpus cases. Its Rust binding exports an empty highlight query; `tree-sitter.json` advertises several bindings absent from the repository, and its MIT license metadata conflicts with the Cargo ISC declaration. Verify license provenance before changing it.
- **Bindings and queries are inconsistent.** Crystal and Nim declare Node bindings in package metadata but only Rust binding files are present. Neither ships a highlight query. V and HolyC expose highlight queries, while LOLCODE exposes an empty one. Audit actual consumer requirements before standardizing APIs.
- **Zed extension ownership is unconfirmed.** `undivisible/zed-extensions` is a fork of the Zed extension registry. Its default branch's four commits ahead of upstream add and update Crepuscularity; its Crystal and Nim entries point to other owners' submodules, and its manifest does not reference these five grammar forks. It was 743 commits behind upstream at inspection. Do not assume updating this registry updates consumers of these grammars; identify the actual extension repositories and pins first.

## Verification limits

Tree-sitter CLI 0.25.10 was used for the parse, corpus and query checks. The 0.26.8 prebuilt CLI could not run on this orb's glibc, and Rust/Cargo were not installed, so Rust binding tests and package builds were not run. Zed itself was not built or exercised. Further syntax, highlight semantics, binding compatibility and consumer integration remain to be audited.
